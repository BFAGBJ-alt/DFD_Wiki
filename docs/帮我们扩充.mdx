本 Wiki 由社区共同维护，欢迎任何人参与补充与修正。内容以「准确、可复现、可维护」为第一原则：
凡是写进 Wiki 的内容，都应当能在游戏中或插件源码中得到验证。

贡献方式有三种，可根据自身情况选择。

## 一、贡献方式

### 方式一：Fork 后提交 Pull Request（推荐）

适合能使用 Git 的贡献者，便于审查与讨论。

1. 打开源码仓库 [BFAGBJ-alt/DFD_Wiki](https://github.com/BFAGBJ-alt/DFD_Wiki)，点击右上角 **Fork**。
2. 将你名下的 Fork 克隆到本地：

   ```bash
   git clone https://github.com/<你的用户名>/DFD_Wiki.git
   cd DFD_Wiki
   npm install
   npm start          # 本地预览：http://localhost:3000
   ```

3. 新建分支并在其上写作，不要直接改 `main`：

   ```bash
   git checkout -b docs/你的主题
   ```

4. 在 `docs/` 下新增或修改条目（`mdx` 格式），素材放到 `static/` 对应目录。
5. 本地确认无误后提交并推送：

   ```bash
   git add -A
   git commit -m "docs: 补充 XXX"
   git push origin docs/你的主题
   ```

6. 回到 GitHub，向 **BFAGBJ-alt/DFD_Wiki 的 `main` 分支** 发起 Pull Request，说明改动内容与依据（游戏内实测截图、源码位置等）。

### 方式二：提交 Issue（不具备 Fork 条件时）

不熟悉 Git、或只是指出问题，可直接在
[Issues 页面](https://github.com/BFAGBJ-alt/DFD_Wiki/issues) 提交 Issue，同样视为有效贡献。

建议在 Issue 中尽量提供：

- 页面标题或链接；
- 问题描述（笔误、数值错误、步骤缺失、贴图错误等）；
- 依据（游戏内实测、插件源码片段、配置项位置）。

我们会在核实后更新对应条目，并在 Issue 中回复处理结果。

### 方式三：参与讨论与校对

对已有条目提出异议、补充截图、指出术语不统一，都可以通过 Issue 完成。
校对类贡献与写作类贡献同等重要。

> 部署仓库 `wiki_page` 仅存放构建产物，其内容每次发布都会被整体覆盖。
> 请勿在该仓库提交 Issue 或 Pull Request，所有讨论请集中在源码仓库。

## 二、内容与 AI 使用规范

本站不排斥 AI 工具，但要求「工具可以加速，判断必须由人负责」。具体约定如下。

### 允许：用 AI 分析源码生成物品数据

`src/data/items/` 下的 `ts` 文件是结构化数据（名称、模型、贴图、链接等），
允许借助 AI 阅读插件源码、`assets` 目录或模型文件后批量生成。

生成结果需满足：

- 字段与 `src/data/items/types.ts` 中的 `ItemDef` 定义一致；
- 物品 id 与游戏中一致，不臆造；
- 同一物品在多个文件间不要重复登记。

### 允许：用 AI 批量生产物品页面，但必须逐条核对

物品类页面（配方、数值、获取方式等）允许批量生成，**但必须自行与游戏内表现
或附属源码逐一核对**后再提交。核对范围至少包括：

- 配方形状、材料数量、产出数量；
- 耗时、耗电等数值；
- 机器归属与合成类型（工作台 / 熔炉 / 机器）；
- 物品贴图与实际游戏贴图是否一致。

未核对的内容不要提交；提交时请在 PR / Issue 中说明核对方式。

### 不允许：用 AIGC 代写教程正文

教程（例如「基础 ME 网络的搭建」这类有先后顺序、有操作步骤、有判断分支的条目）
**必须由撰写者本人亲自完成**。AI 可以用于润色语句、检查错别字，但不得用于生成教程主体。

原因很直接：教程的价值在于「按此操作一定成功」，而这一点只能由真正搭过、
踩过坑的人保证。未经实践验证的教程对其他玩家的伤害远大于留白。

## 三、常用组件

本站内置了一批 Minecraft 相关组件，直接写在 `mdx` 中即可使用。
下述示例中的代码块请原样复制到你的条目中。

### BlockDisplay：等距 3D 方块图标

使用原版模型几何与贴图渲染，非立方体方块（讲台、栅栏、箱子等）也能正确显示形状。
固定视角、不可交互，适合放在正文里做小图标。

```mdx
import BlockDisplay from '@site/src/components/BlockDisplay';

<BlockDisplay item="me_charger" size={100} />
<BlockDisplay block="lectern" size={32} />
<BlockDisplay skull="https://textures.minecraft.net/texture/xxxx" face="east" size={48} />
```

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `item` | `string` | — | 物品库 id（`src/data/items`），自动展开 `block` / `skull` / `name` |
| `block` | `string \| string[]` | — | 原版方块 model id，如 `furnace`、`glass`；数组或逗号分隔字符串可叠加多个模型（后者绘制在上层） |
| `skull` | `string` | — | 自定义头颅皮肤 URL（64×64 PNG）；与 `block` 同时填写时以 `block` 为准 |
| `face` | `'up' \| 'north' \| 'south' \| 'east' \| 'west'` | `'up'` | 头颅朝向：`up` 为落地头（脸朝北）；水平方向表示脸贴在该侧边缘 |
| `size` | `number` | `32` | 图标宽度（px），高度按模型包围盒自适应 |
| `name` | `string` | — | 无障碍名称 / 悬停提示 |
| `className` | `string` | — | 附加的 CSS class |

### StructureViewer：交互式结构查看器

桌面端使用 3D 渲染（可旋转、可点击带 `link` 的方块），移动端降级为静态图与方块名单。
用于展示多方块结构，也支持只展示单个方块。

```mdx
import StructureViewer from '@site/src/components/StructureViewer';

<StructureViewer name="AE/me-network" />
<StructureViewer item="me_drive" />
<StructureViewer block="furnace" label="熔炉" />
<StructureViewer skull="https://textures.minecraft.net/texture/xxxx" face="up" label="玩家头颅" />
```

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `name` | `string` | — | 结构名，读取 `static/structures/<name>.json`；支持子目录，如 `name="AE/me-craft"` |
| `block` | `string \| string[]` | — | 原版方块 model id，可叠加多个模型 |
| `item` | `string` | — | 物品库 id，自动展开方块、名称与链接 |
| `skull` | `string` | — | 自定义头颅皮肤 URL（64×64 PNG） |
| `face` | `'up' \| 'north' \| 'south' \| 'east' \| 'west'` | `'up'` | 单方块模式下头颅朝向 |
| `label` | `string` | — | 名称：桌面端悬停显示，移动端在名单里常驻显示 |
| `link` | `string` | — | 点击方块跳转的 wiki 链接 |
| `color` | `string` | `#888888` | 无模型、无贴图时的纯色回退 |
| `size` | `'sm' \| 'md' \| 'lg' \| number` | 结构 `md`，单方块 `sm` | 画布高度：`sm`=280、`md`=480、`lg`=600，或直接给像素数 |
| `axes` | `ViewerAxis[]` | — | 多轴切换，可多于两条：列表轴用 `options`，数字轴用 `min`/`max` |
| `order` | `string` | — | 后缀顺序模板，如 `"-{b}-{c}-{a}"`；省略时按 `axes` 顺序直接相连 |

`ViewerAxis` 有两种：

```ts
// 列表选择器
{key: 'a', label: '等级', options: [{label: '最大', suffix: '-最大'}, {label: '最小', suffix: '-最小'}]}

// 数字选择器：下拉框列出 min..max（按 step），{value} 会替换为当前值
{key: 'c', label: '阶段', type: 'number', min: 1, max: 3, suffix: '-阶段{value}'}
```

列表选项可以写 `availableWhen` 限制在其他轴某些取值下才出现：

```mdx
<StructureViewer
  name="Logi/元素嬗变"
  axes={[
    {
      key: 'a',
      label: '等级',
      options: [
        {label: '最大', suffix: '-最大'},
        {label: '最小', suffix: '-最小'},
      ],
    },
    {
      key: 'b',
      label: '状态',
      options: [
        {label: '正常', suffix: ''},
        {label: '激活', suffix: '-激活'},
        {label: '融毁', suffix: '-融毁', availableWhen: {a: ['最大']}},
      ],
    },
  ]}
  order="{a}{b}"
/>
```

- `availableWhen` 的键是其他轴的 `key`，值是允许的选项名称（列表轴）或数字（数字轴），可写数组；
- 不满足条件的选项不显示；如果切换其他轴导致已选项失效，会自动跳到该轴第一个可用项（如「最小 + 融毁」会自动变成「最小 + 正常」）。
- `order` 中的 `{key}` 会替换为该轴当前的完整 `suffix`（连字符包含在 suffix 里），不要在模板中重复添加。

结构文件放在 `static/structures/<分类>/<name>.json`（如 `static/structures/AE/me-craft.json`），坐标单位为格，格式如下：

```json
{
  "name": "me-craft",
  "pattern": {
    "controller": {}
  },
  "palette": {
    "controller": {
      "block": "black_stained_glass",
      "label": "ME 控制器",
      "link": "/docs/粘液科技-单方空岛/应用能源/物品/ME控制器"
    }
  },
  "blocks": [
    {"x": 0, "y": 0, "z": 0, "type": "controller"},
    {"x": 1, "y": 0, "z": 0, "item": "me_drive"},
    {"x": 0, "y": 1, "z": 0, "block": "target", "label": "样板接口"}
  ]
}
```

- `palette`（别名 `pattern`）用于预设重复出现的方块，`blocks[].type` 引用预设；两者同时存在时 `palette` 优先；
- `blocks[].item` 引用物品库（`src/data/items`），方块内的内联字段优先于预设与数据库；
- 每个方块可填 `block` / `skull` / `face` / `facing` / `axis` / `color` / `label` / `link`；
- 桌面端结构查看器顶部有分层控制条：可切到单层（按实际存在的 Y 层逐层切换）或回到全部层；移动端在全屏 3D 浮层里同样可用。

#### 一个位置多个候选方块

方块可额外填 `candidates`（候选数组，第一项为默认）和 `interval`（轮换间隔，单位 tick，1 tick = 0.05 秒）：

```json
{
  "pattern": {
    "reactor": {
      "block": "iron_block",
      "interval": 20,
      "candidates": [
        {"block": "iron_block", "label": "待机"},
        {"block": "gold_block", "label": "运行"},
        {"block": "redstone_block", "label": "故障"}
      ]
    },
    "unknown": {
      "block": "stone",
      "interval": 0,
      "candidates": [
        {"block": "stone", "label": "石头"},
        {"block": "cobblestone", "label": "圆石"},
        {"item": "me_drive"}
      ]
    }
  },
  "blocks": [
    {"x": 0, "y": 0, "z": 0, "type": "reactor"},
    {"x": 2, "y": 0, "z": 0, "type": "unknown"}
  ]
}
```

- `interval > 0`：按该间隔在候选之间自动轮换（上面的例子是 20 tick，即 1 秒）；
- `interval` 为 `0` 或 `-1`（或不填）：不轮换，固定显示第一项；鼠标悬停时在画布左上角列出该位置的全部候选；
- 候选数量大于 1 的方块不参与面剔除和合并渲染，由独立组件按当前候选渲染；
- 每个候选与普通方块字段一致，可以写 `block` / `skull` / `item` / `label` / `link` 等；写 `item` 时自动展开物品库里的模型、名称与链接；
- 左上角面板会显示每个候选的图标与名称；点击多候选方块会选中它，暂停自动旋转并让面板常驻，
  点击面板中有 `link` 的名称/图标即可跳转；点击画布其他位置取消选中并恢复旋转。

### 从 litematic 生成结构 JSON

`scripts/litematic_to_structure.py` 把 Litematica 投影文件转成本站的结构 JSON，
只依赖 Python 3 标准库，无需安装额外包。

```bash
python scripts/litematic_to_structure.py <输入.litematic> <输出.json> [--name 名称] [--model-dir 目录]
```

| 参数 | 说明 |
| --- | --- |
| `<输入.litematic>` | 必填。Litematica 投影文件，gzip 或未压缩的 NBT 都可以 |
| `<输出.json>` | 必填。输出路径，目录不存在会自动创建 |
| `--name` | 可选。JSON 的 `name` 字段；省略时优先取投影里的 `Metadata.Name`，否则用输出文件名 |
| `--model-dir` | 可选。方块模型目录，默认 `static/img/Minecraft/block`；材质没放在默认位置时用它指定 |

一次完整流程：

1. 在游戏里保存投影，得到 `.litematic`。
2. 运行脚本，把结果输出到 `static/structures/<分类>/<名字>.json`：

   ```bash
   python scripts/litematic_to_structure.py "NTW_Push.litematic" "static/structures/NTW/NTW_Push.json"
   ```

3. 打开生成的 JSON，按报告补全 `pattern`（见下文）。
4. 在 `mdx` 里嵌入查看器，路径不带 `.json`：

   ```mdx
   import StructureViewer from '@site/src/components/StructureViewer';

   <StructureViewer name="NTW/NTW_Push" />
   ```

5. `npm start` 本地确认显示效果。

生成的 JSON 结构：

```json
{
  "name": "NTW_Push",
  "pattern": {
    "blast_furnace": {"item": ""}
  },
  "blocks": [
    {"x": 0, "y": 0, "z": 5, "type": "blast_furnace", "block": "blast_furnace", "facing": "west"}
  ]
}
```

- `blocks[].type`：投影里的原始方块 id，同时是 `pattern` 的键；
- `blocks[].block`：脚本根据材质推导出的本站模型 id，已经内联写好，不填 `pattern` 也能直接渲染；
- `blocks[].facing` / `axis`：投影中带朝向的方块会写入对应原版属性；
- `pattern` 会按本次实际出现的每个 `type` 生成占位，值为 `{"item": ""}`。

`pattern` 的占位怎么填：

- 想引用本站物品库：把 `item` 改成 `src/data/items` 里的 id，例如 `{"item": "me_drive"}`，
  会自动展开名称、链接、颜色；
- 想直接写模型：把占位换成 `{"block": "furnace", "label": "熔炉", "link": "/docs/..."}`；
- 留空 `{"item": ""}` 时不会展开任何内容，会回退到方块内联的 `block`，不会变成灰色；
- 方块自身的字段优先级高于 `pattern`，同一 `type` 的不同方块可以单独覆盖字段。

脚本会对投影做这些处理：

- **空气方块**不输出（`air`、`cave_air`、`void_air`、`structure_void`）；
- **负 Size**：负号只表示从 `Position` 向负方向延伸，脚本按 Litematica 规则换算绝对坐标；
- **多 region**：按世界坐标展平，重叠格按文件中 region 的顺序“后者覆盖前者”，报告会给出覆盖格数；
- **TileEntity / Entity / PendingTicks**：本站结构 JSON 没有对应数据模型，只统计数量并在报告里列出，不写入 JSON；
- **映射失败**：不会静默丢弃。方块仍保留 `type`，只是不写 `block`，并在报告 `[未映射]` 下列出所有缺少模型的 blockstate；
  补材质或手动填写 `block` 后重新运行即可。

按物品库自动选择 3D 方块图标或平面贴图，可按需显示数量角标与跳转链接。

```mdx
import ItemIcon from '@site/src/components/ItemIcon';

<ItemIcon id="me_drive" />
```

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |

| `item` | `string` | — | 与 `id` 等价，二者写一个即可 |
| `size` | `number` | `32` | 图标边长（px） |
| `count` | `number` | — | 数量，大于 1 时右下角显示角标 |

### RecipeViewer：合成配方

支持有序合成、无序合成与熔炉三种，可附带机器、耗时与耗电信息。

```mdx
import RecipeViewer from '@site/src/components/RecipeViewer';

<RecipeViewer
  recipe={{
    type: 'shaped',
    pattern: ['ABA', 'BCB', 'ABA'],
    materials: {
      A: {id: 'stone'},
      B: {id: 'iron_ingot'},
      C: {id: 'redstone'},
    },
    result: {id: 'me_drive', count: 1},
    machine: 'enhanced_crafting_table',
    time: 10,
    energy: 500,
  }}
/>
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `type` | `'shaped' \| 'shapeless' \| 'furnace'` | 配方类型 |
| `pattern` | `string[]` | 仅 `shaped`：最多三行，每行最多三个字符，空格表示空槽 |
| `materials` | `Record<string, ItemStack>` | 仅 `shaped`：字符到材料的映射 |
| `ingredients` | `ItemStack[]` | 仅 `shapeless`：材料列表 |
| `input` / `fuel` | `ItemStack` | 仅 `furnace`：输入物与燃料（燃料可省略） |
| `result` | `ItemStack` | 产出物 |
| `machine` | `ItemStack \| string` | 所需机器，显示在九宫格左侧；可写机器表 id |
| `time` | `number \| string` | 耗时：数字按秒显示，字符串原样显示（如 `'1m20s'`） |
| `energy` | `number \| string` | 耗电：数字按 J 显示，字符串原样显示（如 `'1k FE'`） |

其中 `ItemStack` 的字段为：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `string` | 物品库 id，自动解析名称与贴图 |
| `name` | `string` | 覆盖显示名称 |
| `texture` | `string` | 覆盖贴图路径 |
| `count` | `number` | 数量，默认 1 |

### ShapedRecipeViewer：任意尺寸有序合成

与 `RecipeViewer` 的 `shaped` 相同，但格数不限于 3×3：`pattern` 可以任意行列，省略时按 3×3 空网格处理。
非 3×3 时会在网格下方按物品 id 汇总每种材料的总量（自动乘以 `count`）。

```mdx
import {ShapedRecipeViewer} from '@site/src/components/RecipeViewer';

<ShapedRecipeViewer
  recipe={{
    type: 'shaped',
    pattern: ['ABCCBD', 'BEFFEB', 'CGHHGC', 'CGHHGC', 'BEIIEB', 'JBCCBK'],
    materials: {
      A: {id: 'logitech_tech_core', count: 64},
      B: {id: 'logitech_transmutator_rod'},
      C: {id: 'logitech_space_plate'},
      D: {id: 'logitech_mass_core', count: 64},
      E: {id: 'logitech_chip_core', count: 4},
      F: {id: 'logitech_lsingularity', count: 4},
      G: {id: 'logitech_pagold', count: 4},
      H: {id: 'NUCLEAR_REACTOR', count: 16},
      I: {id: 'logitech_bisilver', count: 4},
      J: {id: 'logitech_metal_core', count: 64},
      K: {id: 'logitech_smelery_core', count: 64},
    },
    result: {id: 'logitech_transmutator'},
    machine: 'logitech_bug_crafter',
  }}
/>
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `recipe.type` | `'shaped'` | 固定为有序合成 |
| `recipe.pattern` | `string[]` | 可选。任意行列，空格表示空槽；省略时按 3×3 空网格 |
| `recipe.materials` | `Record<string, ItemStack>` | 字符到材料的映射，`ItemStack` 字段同 `RecipeViewer` |
| `recipe.result` | `ItemStack` | 产出物 |
| `recipe.machine` | `ItemStack \| string` | 所需机器，显示在左侧 |
| `recipe.time` / `recipe.energy` | `number \| string` | 耗时 / 耗电，规则同 `RecipeViewer` |

### 物品库数据

组件里用到的 `item` / `id` 都来自 `src/data/items/`。新增物品时按下表字段书写：

```ts
// src/data/items/example.ts
import type {ItemDef} from './types';

export const items: Record<string, ItemDef> = {
  example_item: {
    name: '示例物品',
    block: 'furnace',          // 3D 方块模型 id（可选）
```

| `skull` | `string` | 自定义头颅皮肤 URL |

## 五、附：原版材质目录结构

`static/img/Minecraft/` 整个目录不进版本库，需要按下面的结构自行部署。
附属（SlimeFun）材质打包在仓库根目录，二选一解压到 `static/img/Minecraft/` 即可：

| 文件 | 大小 | 说明 |
| --- | --- | --- |
| `SlimeAssets.zip` | 约 14.6 MB | 系统自带解压，推荐 |
| `SlimeAssets.7z` | 约 6.8 MB | 体积更小，需 7-Zip（Win11 新版资源管理器可直接打开） |

两个压缩包内容相同，解压后根目录都是 `SlimeFun/`。

```text
static/img/Minecraft/
├── block/                      # 方块模型与贴图（3600 个文件）
│   ├── stone.json              # 方块模型：parent / textures / elements
│   ├── stone.png               # 方块贴图（16×16）
│   ├── water_still.png         # 动画贴图：竖向长条，每帧 16×16
│   └── water_still.png.mcmeta  # 动画帧序与时长
├── item/                       # 物品平面贴图（792 个 PNG）
│   └── apple.png
├── items/                      # 物品定义（1505 个 JSON，1.21+ item definition）
│   └── acacia_boat.json        # 指向 minecraft:item/acacia_boat
├── model/
│   └── item/                   # 物品模型（1283 个 JSON）
│       └── acacia_boat.json    # 指向 item/ 下的贴图
├── entity/                     # 实体贴图（631 个文件，按实体名分组）
│   ├── chest/
│   ├── player/
│   ├── villager/
│   └── ...
└── SlimeFun/                   # 附属材质：由 SlimeAssets.zip / .7z 解压得到
    └── assets/<命名空间>/textures/...
```

> 素材来源 Minecraft 1.21.11，自行根据该结构部署材质。
> 解压压缩包后根目录即 `SlimeFun/`，最终应得到 `static/img/Minecraft/SlimeFun/assets/...`。
> 整个 `static/img/Minecraft/` 都被 `.gitignore` 忽略；缺少材质时构建仍可进行，
> 但页面中的方块与物品图标会缺失。
